## 二、推理容器 CPU 异常（排查与修复）

### 现象

- 单路 `visual-dps-infer-cam3` CPU **~1400%**（16 核 WSL、CPU 推理）；重启容器、恢复 ffmpeg 推流均无效。
- 与「8 路推理总负载」不可比：8 路抢核时 docker 单容器统计偏低；单路时 ORT 默认 spin 占满整机。

### 根因

- **非 MediaMTX / 非 RTSP 解码**（仅解码 ~4% CPU）。
- rtmlib 创建 det/pose 两个 `InferenceSession` **未设 SessionOptions** → ORT 默认占满逻辑核 + **`allow_spinning=1` 用户态空转**（~30 线程 `wchan=0`）。
- 实测单次 det+pose ~107ms、pose ~1.6fps，不应长期 14 核满载。

### 修复

- 新增 `services/inference_backends/ort_session.py`：patch `InferenceSession`；默认 **intra=2、inter=1、allow_spinning=0**。
- `rtmpose_onnx_backend` 加载模型前 `install_ort_session_defaults()`。
- `inference_container_service` 注入 `INFERENCE_ORT_*` / `OMP_WAIT_POLICY=PASSIVE` 并挂载 `ort_session.py`。
- **验证**：cam3 CPU **~1450% → ~7–11%**，pose:stream 正常。

### 可调 env（`.env.example`）

- `INFERENCE_ORT_INTRA_THREADS`（默认 2）
- `INFERENCE_ORT_INTER_THREADS`（默认 1）
- `INFERENCE_ORT_ALLOW_SPINNING`（默认 0）
