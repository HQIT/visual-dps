## 三、本日联调动作与运行方式（4841de6a 分支）

### 栈组成

| 组件 | 方式 |
|------|------|
| Redis + MediaMTX | `docker compose up -d redis mediamtx` |
| UI | 宿主机 `PYTHONPATH=. uvicorn main:app --port 8046`（**勿** `app_factory:create_app --factory`） |
| event-worker | 宿主机 `COLLISION_LOG=1 PYTHONPATH=. python -u event_worker.py`，日志 tee 至 `localdata/logs/event-worker-*.log` |
| 推理 | 手动 `docker run` **`visual-dps-infer-cam1`**，镜像 **`visual-dps-inference-lite-gpu-onnx:20260529-165748-5c6b720-ultra84`**，`INFERENCE_BACKEND=rtmpose_m` |
| 推流 | cam1 单次 / 循环 ffmpeg → `rtsp://127.0.0.1:8554/cam1`；与标注对齐建议 **640×360**（`annotation_size`） |

### 宿主机环境要点

- UI / worker：`unset REDIS_URL` + `/etc/hosts` 增加 `127.0.0.1 redis`，或 UI 单独 `REDIS_URL=127.0.0.1` 且**仅用手动 docker 启推理**（避免 `127.0.0.1` 传入 infer 容器）。
- 推理容器 Redis：**`REDIS_HOST=redis`**（Docker 网络内），**不要** `REDIS_URL=@127.0.0.1`。
- 宿主机 UI：`unset MEDIAMTX_INTERNAL_HOST`；WebRTC 需 `MEDIAMTX_PUBLIC_HOST` 与 `mediamtx.yml` 的 `webrtcAdditionalHosts` 一致（本机 **192.168.31.12**），并放行 **8189 UDP/TCP**。

## 四、联调现象与结论（待产品/代码跟进）

| 现象 | 结论 |
|------|------|
| UI `REDIS_URL=127.0.0.1` 经 API 启推理 | infer 容器内连不上 Redis（127.0.0.1 指向容器自身） |
| `unset REDIS_URL` 且无 hosts | 宿主机 UI `redis` 解析失败 → LiveHub 报错 |
| WebRTC 黑屏 | 多为 `MEDIAMTX_PUBLIC_HOST` 与浏览器访问 IP 不一致或 ICE 8189 未通 |
| 标注与视频 ROI 错位 | cam1 标注 **640×360** + 源为 1.34 摄像头；推流 640×480 或换 MP4 需重标或改 scale |
| 单次推流结束 infer 不退出 | **设计如此**：RTSP 模式断流后空转 + 重连（404 DESCRIBE），非文件 EOF；需 `docker stop visual-dps-infer-cam1` |
| 推理启动 → 首包 pose 延迟 | 冷启动模型加载 + FFmpeg NVDEC 失败回退 OpenCV + 首帧 warmup；日志停在「推理参数」后才有 XADD |
| infer 日志「流地址与标注不一致」 | 警告，不阻断；测试 MP4 与 `source_info` 原 RTSP 不同 |
