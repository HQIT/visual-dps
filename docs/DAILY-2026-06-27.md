# 工作日报（2026-06-27）

## 一、离线评测（/bench）全链路

- **后端**：新增 `benchmark_runner.py`、`services/benchmark_store.py`（SQLite）、`services/benchmark_routes.py`（上传/预览/创建/重跑/回放/导出 API）。
- **推理**：`inference_service.py` 支持本地 file 源；读帧同线程记录 `POS_MSEC`/`POS_FRAMES`，发布 pose 时带 `run_id`、`video_time_sec`；benchmark 与 live 总线隔离（`pose_bus.py`）。
- **Event Worker**：订阅 benchmark pose，按 run 标注快照做碰撞/告警并落库 `benchmark_pose_frames` / `benchmark_alarms`。
- **前端**：`BenchPage.jsx`（新建评测 + 历史列表）、`BenchReplayPage.jsx`（视频回放 + 帧事件侧栏）；`MonitorPreviewStage` 支持文件预览与 overlay。
- **时间轴**：新增 `services/video_time.py`；回放优先使用落库 `video_time_sec`，避免 `frame_idx→0s` 硬对齐导致骨架与浏览器 `<video>` 错位。

## 二、回放帧定位与侧栏 seek

- **根因**：侧栏点击帧 N 时 HTML5 seek 遇关键帧回退，二分查找左边界导致选中上一帧；早期 `POS_MSEC` 在 async 推理后读取，demux 可能跳到 ~10s，旧库出现 `frame_idx=1, video_time_sec=10`。
- **`web/src/lib/benchTime.js`**：`findFrameAtPlaybackTime` 改右边界二分；新增 `seekSecForFrame`（帧时间窗中点）、`findFrameByIdx`。
- **`BenchReplayPage.jsx`**：侧栏点击锁定 `pinnedFrameIdx`，seek 到目标帧时间窗中点，减轻 off-by-one。
- **注意**：已跑完的历史 run 若库内 `video_time_sec` 错误，需 **按当前代码重跑** 后时间轴才可靠。

## 三、评测运营能力（导出 / 筛选 / 参数）

- **事件导出**：`services/benchmark_export.py` + `GET /api/benchmark/runs/{id}/export`，UTF-8 BOM CSV（Excel 可直接打开），列含视频时间、`box_id`、碰撞/告警；回放页「导出 Excel」按钮。
- **货框筛选**：回放侧栏支持按 `box_id` 搜索/下拉筛选，与碰撞/告警类型筛选叠加（`benchEvents.js`）。
- **告警门控参数**：
  - 系统设置（`runtime_config_service.py` + `cameraSettings.js`）新增 **告警连续碰撞帧数**、**告警冷却帧数**（冷却允许 **0**）。
  - 「新建评测」表单同步两项；创建/重跑写入 run `config` 快照。
  - **`collision.py`**：`alarm_cooldown_frames=0` 表示无冷却（不再 `max(1,…)` 强制为 1）。
  - **`event_engine/worker.py`**：benchmark 上下文优先读 run `config` 告警阈值，否则回退 runtime / `app_config`。
- **重跑逻辑**：不再默认套系统全局参数；列表/回放重跑使用「新建评测」区当前值（`benchCreateParams.js` + `sessionStorage` 持久化），`POST .../rerun` 接受 JSON body（模型、姿态间隔、告警参数）。

## 四、排查说明（文档级）

- **侧栏连续多帧「碰撞」但迟迟不「告警」**：
  - 告警需同时满足 **连续 N 帧碰撞**（默认 3）与 **冷却帧**（旧默认 6；当前 `app_config` 已改为 0）。
  - 侧栏只展示 **有事件的 pose 帧**；中间某帧手腕离开货框会 **重置连续计数**（文档 6/26 已述）。
  - **告警帧 UI 只显示「告警」**，不重复显示「碰撞」；第一次告警可能在列表更上方（如 frame 801），截图从 802 起会误以为「5 帧未告警」。
  - 用 DB 重放 `CollisionProcessor` 验证：`cooldown=6` 时 801 告警、807 再告警与库内一致；`cooldown=0` 应几乎每帧可告警——**改参数后须重启 event_worker 并重跑评测**，processor 在 run 开始时按当时配置创建。
- **评测 vs 推流评测**：离线 `/bench` 适合碰撞/告警验证与回放；live 链路日志可对照，但回放 UI 依赖 benchmark 落库。
